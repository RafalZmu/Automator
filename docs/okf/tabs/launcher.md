# Launcher — slot 1

Source of truth: `docs/tabs/launcher/` in the repository. This concept is generated by `scripts/build-okf.mjs`; edit the source files, then run `npm run okf:build`. Relative links inside the embedded text point at repository paths, not bundle concepts.

## Behavior and code map

The Launcher binds short letter aliases to installed apps, EXEs, and shortcuts. It can minimize the foreground app, restore/maximize an app already running, or launch and maximize a new app. The app catalog is opened with /; aliases are edited on app rows.

When the compact panel opens, its home surface is Global Action Search. That surface searches actions from all tabs and does not consume a numbered slot. Typing a unique command runs it; selecting a tab-specific result routes to that tab. The normal app-alias flow remains available on slot 1.

While a text-like field (text input, search, number, textarea, select, or contenteditable) has focus in the open launcher, digits 1–9 and `/` type into that field instead of selecting a tab or opening the catalog. Escape still closes the panel. Up and Down (row switching, only when there is more than one row of tabs) also yield to text fields, except an empty launcher, Quick Actions or tab search box. The renderer reports text-entry focus to the backend through `launcher/setWindowContext` (`textEntryFocused`), and the native keyboard hook uses it; buttons and checkboxes do not change the behavior.

The compact launcher uses a fixed 760×800 preferred window size and clamps to the selected display's work area when needed. Each time the panel opens, it is placed centered horizontally under the pointer on the display the pointer is on. Moving the pointer while the panel is open does not move it. The active tab view scrolls vertically; the topbar, tab selector, command bar, and footer stay in place.

## Contributor rules

Read the root AGENTS.md first. This guide covers the slot 1 app launcher and its boundary with global action search.

### Preserve the launcher contract

- Keep app aliases separate from tab commands. App aliases remain letters-only and are resolved by the launcher; global commands are registered through the tab command registry.
- Keep the numbered slots 1–10 available for tab selection (keys 1–9 and 0). Global Action Search is a home surface, not another tab.
- Digits 1–9 and `/` must not be consumed globally while a text-entry control is focused. The renderer's `textEntryFocused` flag (`ui/App.tsx` focus reporting → `electron/main.ts` → `launcher/setWindowContext` → `NavigationKeyPolicy.Decide`) carries that state; Escape always still closes.
- The panel opener, native keyboard hook, activation, and foreground restoration belong to the desktop host/backend. Do not replace them with renderer-only keyboard listeners.
- Preserve Tab 1 catalog behavior, custom EXE/shortcut binding, app-row shortcut removal, and launch/restore/minimize semantics.
- Keep launcher and Workspace window state separate where the host contract says it is per-window.
- Keep the compact launcher fixed at its 760×800 preferred size; preserve work-area clamping for smaller displays.
- Keep the topbar, tab selector, command bar, and footer outside the active tab view's vertical scrolling area. Active view roots must remain vertically scrollable.
- Add regression coverage for alias matching, app activation, and command routing when changing these flows.
- Add regression coverage for preferred panel bounds, fixed-size behavior, and active-tab scrolling when changing launcher geometry.
